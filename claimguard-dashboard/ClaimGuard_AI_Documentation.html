1. Business Problem

Healthcare providers submit insurance claims that may have missing documentation, incomplete coding, or requirements that don't align with payer policy. Denials and rework delay reimbursement and consume billing-team capacity.

ClaimGuard AI is a human-in-the-loop pre-submission review assistant. It uses deterministic data-quality checks, structured claim retrieval, and retrieval-augmented generation over authoritative Medicare coverage documents to identify documentation gaps before claims are submitted.

6. AI Design Decisions

1. Deterministic rules first, LLM second

9 of 15 requirements can be checked with SQL — free, instant, and deterministic. The LLM is only called for requirements needing clinical note interpretation. Findings are flagged as IS_DETERMINISTIC so reviewers know which are guaranteed correct.

2. Chunking by logical section, not fixed length

Policy documents are split by natural sections (e.g., "Qualifying Blood Gas Criteria - Group I") rather than fixed token counts. Each chunk is self-contained and maps to a citable section heading.

3. Metadata attributes for filtered retrieval

Each chunk carries POLICY_NUMBER, JURISDICTION, EFFECTIVE_DATE, and PAYER as filterable attributes. Semantic similarity alone is not sufficient for policy documents — the agent filters to ensure only applicable policies are retrieved.

4. Hybrid search (vectors + keywords + reranking)

Cortex Search combines cosine similarity (semantic match), BM25 text matching (exact terms like "E1390"), and LLM reranking. This handles both natural language queries and exact code lookups.

5. Human-in-the-loop, not autonomous

The agent produces findings; a human reviewer makes the final call. Status flow: Agent → PASS / ISSUE_FOUND / NEEDS_VERIFICATION → Human → ACCEPT / REJECT / ESCALATE.

6. Views over Marketplace data (zero-copy)

CORE tables are views over the Marketplace dataset, eliminating storage costs. The semantic view adds meaning without duplicating data.

7. Audit trail by design

Every review stores an INPUT_SNAPSHOT, POLICY_VERSIONS_USED, and AGENT_VERSION. Every finding includes a POLICY_CITATION linking to the specific policy passage.
